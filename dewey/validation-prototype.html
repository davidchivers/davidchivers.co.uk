Explicit APIs

All functions below live in code/analysis/construction_validation.py. Contract failures raise ConstructionValidationError (a ValueError). Omitted mandatory Python arguments raise TypeError; neither failure grants cache acceptance. Callers must stop or rebuild separately in an approved new location, never treat an exception as permission to reuse.

API Accepted contract and fail-closed behavior
strict_json_loads(payload) Requires raw JSON text/bytes. Duplicate decoded keys at any depth, nonstandard NaN/Infinity constants, overflowed numbers and malformed JSON fail. Preparsed dictionaries are refused because duplicate evidence is already lost.
parse_origin_map(payload, *, null_policy="reject", allow_numeric_strings=False) Numeric, finite, nonnegative weights and nonempty string origin keys. Positive weights retained in source order; zero weights omitted. Duplicate keys always fail. Null/string coercion is disabled by default. Explicit null dropping and numeric-string acceptance are separately declared policies; quoted NaN/Infinity and overflow still fail. Total overflow also fails. An empty map is not an imputed zero diversity index.
validate_weighted_values(values, weights) Equal nonempty lengths, finite numeric values, finite nonnegative weights and positive finite total. Rejects booleans, coercions and nonfinite values even at zero weight. No silent case deletion.
weighted_mean(values, weights) Small arithmetic contract using normalized weights and finite summation; not a new POI-index builder.
validate_alignment(flow_ids, metadata_ids, *, source_rows, run_mode, max_pois) Full input sequences must exactly match the independently declared source length, have unique nonempty IDs, and match in order. No sorting or truncation. Returns immutable source/output counts and ordered-ID SHA-256 receipts.
json_sha256(value) Finite JSON canonicalization: sorted mapping keys, retained list order, ASCII encoding and compact separators. Distinguishes JSON boolean versus numeric config values.
cache_identity(request) Validates the mandatory request and fingerprints it with manifest version 1. Every input/code/config/scope field and explicit max_pois participates. Full and partial keys differ. This function does not locate or write a cache.
observe_output(payload, *, ordered_ids, schema) Hashes supplied bytes and records byte length, independently decoded row count, ID-order hash and schema hash. Pure in-memory evidence helper, not a Parquet reader.
validate_cache_contract(manifest_json, *, expected_request, observed_output, allow_partial=False) Requires raw manifest, independent current request and independently observed artifact evidence. Returns an immutable CacheAcceptance only on an exact complete match. Missing, legacy, stale, malformed and incomplete evidence fails; partial reuse requires explicit opt-in.

Partial mode means a strictly positive max_pois < source_rows and the exact leading prefix. Full mode requires an explicitly present max_pois=null. A cap equal to or exceeding the universe is conservatively rejected as partial, not silently promoted to full. Even partial runs require alignment of both full input sequences, so a selected prefix cannot hide trailing metadata or later ID mismatches. Empty universes are not supported by this prototype.

Manifest contract

Manifest version 1 has exactly manifest_version, request, cache_key, run and output. Missing and unknown fields fail.

  • Request: input_sha256, code_sha256, nonempty resolved config, config_sha256, run_mode, explicitly present max_pois, scope, and output_schema_sha256.
  • Minimum input roles: flows, metadata, lookup. Minimum code roles: builder, validator. Additional dependencies may be included and affect identity; the caller is responsible for enumerating the complete dependency closure.
  • Scope: name, year, full source rows and ID-order hash, planned output rows and ID-order hash, and explicit unique expected work-unit identifiers.
  • Run: nonempty run ID; status exactly complete; scope_complete literally true; full_dataset_complete literally true only for full mode; exact completed-unit set without duplicates; empty failed/skipped units; processed and written row counts equal the planned output count.
  • Output: actual byte SHA-256 and length, row count, schema hash and ID-order hash. Claims must match independent observations and the planned scope/schema.

Run units may finish in any order; venue IDs may not change order. Scope completeness and full-dataset completeness are distinct. Partial opt-in does not permit a partial cache to satisfy a full request or a different cap.

The two output examples are invented JSON fixtures, not production manifests. Their builder hash identifies the synthetic test fixture code; their validator hash identifies this prototype. synthetic_inputs.json contains the invented objects whose canonical bytes are fingerprinted. No manifest is manufactured for historical production outputs.

Limits and integration gate

Passing tests establish only these invented-input contracts. No raw-weekly replication, real anomaly prevalence, final-file validation, annualization semantics, demographic missingness policy, or causal claim is established.

This is an in-memory prototype with materialized ID lists and no Parquet adapter, atomic output/manifest transaction, concurrency control or cache migration. Floating-point arithmetic is not an exact-integer count engine. The generic schema/ID evidence helper cannot prove that caller-supplied IDs and schema came from the supplied bytes; a future approved adapter must decode and bind them. Likewise hashes do not authenticate a producer, prove its supplied scope is complete, or identify omitted dependencies. Freeze the complete input/code/runtime/config inventory and expected scope independently; do not derive the expected request by copying an untrusted manifest.

Any production integration needs separate approval, an approved local I/O adapter, unchanged historical outputs, real file-boundary/integration tests, and explicit handling of publication/commit of a complete manifest. None is claimed here.
