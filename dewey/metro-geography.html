19 October 2026. Public population-reference construction and a separate approved 2019 final-file geography audit. This advances the larger-city question in note 93; it is not a new regression or a test of attitudes.

Bottom line

We now have a checked population denominator for 2017-2019, on one explicit metropolitan definition. We should not simply merge it to an old MSA code and assume the geography is identical.

The common-reference choice is September 2018 OMB delineations, with Vintage 2019 Census population estimates for July 1 of each study year. That provides 384 metropolitan and 542 micropolitan areas in the 50 states plus DC. The proposed city-size analysis uses metros, not all CBSAs. A CBSA can be either metro or micro; neither a venue count nor an arbitrary recorded MSA code is a population measure. Puerto Rico is outside this particular population source.

The historical mismatch concerns Bedford city’s conversion to a town within Bedford County. It illustrates why a changed county-key set is not necessarily a physical change in a metro’s footprint. No historical population crosswalk has been improvised. The older project PUMS context uses an MSA2013 bridge; that construction is retained, not silently relabelled as MSA2018.

The separate 2019 POI check

The existing permission allowed a read-only check of two columns only: recorded destination county and recorded area code. It covered the full 2019 final file and took 109.25 seconds including source fingerprinting. No visit, income, race, worker, coordinate or individual identifier was read for this check. The pending annual-flow and ACS files were not processed.

The fixed question is whether each recorded county belongs to its recorded area under the September 2018 reference. Missing or malformed keys, unsupported counties/codes, counties outside any CBSA and actual county/code disagreement are all retained in the denominator. They have separate private diagnoses, but the only proposed disclosure is a single national binary profile.

This is the single exact national profile cleared by independent review. The compatible group includes both metropolitan and micropolitan areas; it is not the future metro-only regression sample. The reviewer independently reclassified the authorized private geography aggregate, reproduced both counts and checked the combination with seven named existing public notes. All 20 correspondence checks passed. Detailed diagnoses and code identities remain private; the review is not a formal privacy guarantee.

Even a compatible pair does not prove accurate geocoding, establish the producer’s boundary vintage or validate every previous result. Conversely, not demonstrated compatible does not mean the record is erroneous: it includes out-of-scope and non-CBSA observations as well as unresolved keys/conflicts. Neither group is weighted by visits. No row has been corrected, dropped from the original data or assigned a replacement area.

What to do with this

  1. Use the common public reference as a candidate, not an automatic merge. Keep metro/micro classification, population year and boundary vintage explicit. Resolve the recorded-geography convention before an inference sample is fixed. Retain a flow diagram of all exclusions.
  2. Ask the producer for the actual geography assignment step. We need its dated delineation/crosswalk, the meanings of MSA_CODE and destination_county, and the handling of non-CBSA/unmatched areas. A known code is not enough, and choosing the vintage with the highest match rate would not establish provenance. This is part of the original replication request, not a request to rerun everything blindly.
  3. Then reconstruct the income-group masses and run the planned split. The file-to-file adapter has passed artificial tests, but its annual-flow and ACS-lookup approval is still pending. A population lookup cannot replace group-by-venue masses. County subdivisions remain too coarse to identify a shared shopping centre or a genuine feasible menu.

The economic question remains: does separation in larger cities occur across service types, across destination areas, or between establishments within an area and service type? The present work strengthens the denominator and merge checks needed to ask it. It does not answer which component dominates, establish preferences for co-patrons, or show that adding venues causes sorting.

Verification and limits

The public construction was reproduced from staged bytes with identical hashes for all seven derived tables. A separate reviewer used direct workbook/CSV reading and integer arithmetic. Both main and independent tests pass. The two-column audit separately passed artificial normalization, conservation, fail-closed source and disclosure tests after two documented repairs.

Originals and prospective protocols remain unchanged. Public reference validation, private recorded-field compatibility, accurate physical location and full weekly-to-annual replication are four different claims. Only the first two are addressed here, within their stated scope. Prior failed gates, nulls, correction 70a, the negative equal-county validation and the home-area versus personal-income limitation remain in force.
